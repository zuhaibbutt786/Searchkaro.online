SQL Server Data Types for Mixed Integer and Float Values

Learn which SQL Server type stores integers and decimals efficiently in a single column.

Numeric Types Overview

SQL Server offers several numeric types: INT, BIGINT, FLOAT, REAL, DECIMAL, NUMERIC. INT and BIGINT store whole numbers; FLOAT and REAL store approximate binary floating‑point; DECIMAL and NUMERIC store exact decimal values with defined precision and scale.

Why Not FLOAT for Mixed Data

FLOAT/REAL use binary representation, leading to rounding errors for values like 0.1. They also consume 4 or 8 bytes regardless of precision, which can waste space when many integers are stored.

Best Choice: DECIMAL or NUMERIC

DECIMAL and NUMERIC are synonyms; they store exact decimal values. Specify precision (total digits) and scale (digits after decimal). For mixed integers and decimals, choose a precision that covers the largest expected value and a scale that covers required decimal places.

-- Example: store up to 12 digits with 2 decimals
CREATE TABLE Sample(
    Value DECIMAL(12,2) NOT NULL
);

Inserting Mixed Values

Both integers and decimals are accepted. SQL Server pads missing decimal places with zeros.

INSERT INTO Sample (Value) VALUES
    (15),
    (15.5),
    (12.3),
    (17),
    (19.8);

Performance & Storage

DECIMAL(12,2) uses 6 bytes. Larger precision increases storage. For values that never exceed 10^12, DECIMAL(12,2) is efficient. If you need more than 2 decimal places, increase scale accordingly. Avoid FLOAT unless you need extreme range and can tolerate precision loss.

Takeaway: Use DECIMAL(precision,scale) to store both integers and decimals accurately and efficiently.

People also ask

Can I use INT for all values?

INT only stores whole numbers; decimals would be truncated.

Is NUMERIC different from DECIMAL?

No, they are identical in SQL Server.
