Git Bash on Windows: Why .bashrc Isn’t Executed

Git Bash starts a login shell, so .bashrc is ignored unless you source it from .bash_profile.

Bash Startup Order

When Bash launches, it first checks if it is a login shell. For a login shell it reads /etc/profile, then ~/.bash_profile, ~/.bash_login, or ~/.profile. A non‑login shell reads ~/.bashrc. Git Bash opens a login shell by default.

Why .bashrc is Skipped

Because Git Bash runs as a login shell, it never reads ~/.bashrc unless a login file explicitly sources it. That explains why your variable is missing after a fresh start.

Fix: Create a .bash_profile

Add a simple profile that sources your rc file.

echo 'source ~/.bashrc' >> ~/.bash_profile

Export Variables Correctly

Variables defined in .bashrc need to be exported to be visible to subshells.

echo 'export ZZZTESTVAR=234' >> ~/.bashrc

Quick Checklist

1. Ensure the file name is .bash_profile, not .bash_profile.txt. 2. Add "source ~/.bashrc" to the profile. 3. Use export for environment variables. 4. Restart Git Bash and verify with `echo $ZZZTESTVAR`.

Takeaway: Add a .bash_profile that sources .bashrc and export variables to make Git Bash load your settings.

People also ask

Does .bashrc run automatically in Git Bash?

Only for non‑login shells; Git Bash starts a login shell.

How do I run custom commands on Git Bash startup?

Place them in ~/.bash_profile or source ~/.bashrc from that file.

Why isn’t my variable exported to child processes?

Add the export keyword in .bashrc.
