Use Table Variable in Dynamic SQL on SAP HANA

Learn why a table variable can’t be referenced in dynamic SQL and how to work around it with temporary tables or subqueries.

Why the Error Happens

In SQLScript a table variable is a compile‑time construct. The dynamic SQL engine parses the string at runtime and only scalar parameters can be bound to it. A table variable is therefore not a valid binding target and the statement fails with an "invalid table reference" error.

Common Fixes

There are two practical ways to get the data into a dynamic query: 1. Create a temporary table, copy the table variable into it, and reference that temp table in the dynamic SQL. 2. Embed the table variable directly in the static part of the query and use dynamic SQL only for the rest of the statement.

Using a Temporary Table

Create a global temporary table, insert the rows from the table variable, and then build the dynamic statement to read from that temp table.

-- Create temp table once per session
CREATE GLOBAL TEMPORARY TABLE #tmpCustomer (
    customer_id NVARCHAR(20)
) ON COMMIT PRESERVE ROWS;

CALL PROCEDURE A();
BEGIN
    -- Load table variable
    VAR_TAB = SELECT customer_id FROM table_A;

    -- Copy into temp table
    INSERT INTO #tmpCustomer SELECT * FROM :VAR_TAB;

    -- Build and execute dynamic SQL
    DECLARE sql NVARCHAR(4000);
    sql = 'SELECT * FROM #tmpCustomer';
    EXECUTE IMMEDIATE sql;
END;

Static Subquery Alternative

If you only need to add a WHERE clause or similar, keep the table variable in the static part and let the dynamic part supply the rest. For example:

CALL PROCEDURE A(); BEGIN VAR_TAB = SELECT customer_id FROM table_A; EXECUTE IMMEDIATE 'SELECT * FROM table_B WHERE customer_id IN (SELECT customer_id FROM :VAR_TAB)'; END;

Best Practices

Always clean up temporary tables after use to avoid session bloat. Use the ON COMMIT PRESERVE ROWS clause if you need the data across multiple statements within the same session. Keep the dynamic part minimal to reduce parsing overhead.

Takeaway: Table variables cannot be bound in dynamic SQL; use a temporary table or embed them in static SQL instead.

People also ask

Can I use a table variable directly in EXECUTE IMMEDIATE?

No – only scalar parameters are supported. Use a temp table or static subquery instead.

What if I need to return the result set to the caller?

Store the result in a temporary table and SELECT from it after the dynamic execution, or use a RETURN statement that reads from the temp table.
