Remove Non‑Alphabetic Characters in SQL Server – Quick & Clean Methods

Learn how to strip every non‑alphabetic character from a string in SQL Server using built‑in functions or a lightweight scalar function. The guide covers both alphabetic and alphanumeric filtering techniques.

Why Clean Strings Matters

Data quality often hinges on removing stray symbols before analysis or reporting. Non‑alphabetic or non‑alphanumeric noise can break joins, skew aggregations, and inflate storage. A consistent approach keeps ETL pipelines simple and reliable.

TRANSLATE – The Modern One‑Liner

SQL Server 2017 introduced TRANSLATE, which maps each source character to a replacement. By mapping every unwanted character to an empty string, you can delete them in a single statement.

SELECT TRANSLATE('Abc123!@#', '0123456789!@#', '') AS Cleaned;
-- Result: Abc

XML PATH Set‑Based Filter

For earlier versions, a set‑based trick uses XML PATH to rebuild the string from only allowed characters. This avoids a cursor or row‑by‑row function call.

DECLARE @s NVARCHAR(MAX) = 'Abc123!@#';
SELECT
  (SELECT SUBSTRING(@s, v.n, 1)
   FROM (SELECT TOP (LEN(@s)) ROW_NUMBER() OVER (ORDER BY (SELECT NULL)) AS n
         FROM sys.all_objects) v
   WHERE PATINDEX('%[A-Za-z]%', SUBSTRING(@s, v.n, 1)) > 0
   FOR XML PATH(''), TYPE).value('.', 'NVARCHAR(MAX)') AS Cleaned;
-- Result: Abc

Scalar Function for Reuse

When you need to apply the same logic across multiple queries, a scalar UDF keeps the code DRY. The function loops through each character, appending only those that match a pattern.

CREATE FUNCTION dbo.RemoveNonAlpha (@input NVARCHAR(MAX))
RETURNS NVARCHAR(MAX)
AS
BEGIN
  DECLARE @pos INT = 1, @len INT = LEN(@input), @out NVARCHAR(MAX) = '';
  WHILE @pos <= @len
  BEGIN
    IF SUBSTRING(@input, @pos, 1) LIKE '[A-Za-z]'
      SET @out = @out + SUBSTRING(@input, @pos, 1);
    SET @pos = @pos + 1;
  END
  RETURN @out;
END;

SELECT dbo.RemoveNonAlpha('Abc123!@#') AS Cleaned;  -- Abc

Performance & Version Considerations

TRANSLATE is fastest on 2017+ because it runs in a single pass. The XML PATH method is set‑based and avoids CLR overhead but can be slower on very large strings. Scalar functions are convenient but may incur row‑by‑row cost; index hints or CROSS APPLY can mitigate this.

Takeaway: SQL Server offers multiple efficient ways to cleanse strings—choose the method that matches your version and performance needs.

People also ask

Can I remove digits only, keeping letters?

Yes, use TRANSLATE with digits mapped to '' or a regex‑style function that keeps only [A-Za-z].

Is there a way to keep spaces between words?

Include a space in the allowed set: TRANSLATE(..., '0123456789!@#', '') or adjust the pattern to '[A-Za-z ]'.

Will these methods affect Unicode characters?

TRANSLATE and XML PATH work with NVARCHAR, so Unicode letters are preserved. Ensure your pattern includes the appropriate Unicode ranges if needed.
