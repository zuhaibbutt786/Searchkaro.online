Push & Pull Docker Images to GitLab Registry Using PAT

Use a personal access token (PAT) with API scope to authenticate Docker pushes and pulls to GitLab's container registry.

Understanding the Error

When Docker tries to authenticate against GitLab, the registry expects HTTP Basic credentials. A 2‑factor enabled account will reject a password that is not a PAT, leading to "unauthorized: HTTP Basic: Access denied". The message "You must use a personal access token with 'api' scope" confirms that the credential type is wrong. SSH keys are for Git over SSH, not for the Docker registry.

Creating a Personal Access Token

1. Go to *User Settings → Access Tokens* in GitLab. 2. Give the token a name, set an expiry, and check the **api** scope. 3. Copy the generated token; it will never be shown again. 4. Store it securely (e.g., as a GitLab CI variable or in a local .env file).

# Example of storing in a local .env file
export GITLAB_PAT=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx

Logging In with Docker

Docker requires the registry URL, username, and the PAT as the password. The registry URL is either `registry.gitlab.com` for the default registry or your custom domain. Use `--password-stdin` to avoid exposing the token on the command line.

echo $GITLAB_PAT | docker login registry.gitlab.com -u $GITLAB_USER --password-stdin

Tagging, Pushing, and Pulling Images

After a successful login, tag your local image with the GitLab registry path and push. Pulling follows the same pattern.

# Tag the image

docker tag myapp:latest registry.gitlab.com/$GITLAB_USER/mygroup/myapp:latest

# Push to GitLab

docker push registry.gitlab.com/$GITLAB_USER/mygroup/myapp:latest

# Pull the image

docker pull registry.gitlab.com/$GITLAB_USER/mygroup/myapp:latest

CI/CD Integration

In a GitLab CI pipeline you can use predefined variables to avoid hard‑coding credentials. The variables `CI_REGISTRY`, `CI_REGISTRY_USER`, and `CI_REGISTRY_PASSWORD` are automatically populated in runners that have permission to push to the registry.

# .gitlab-ci.yml snippet
image: docker:latest
services:
  - docker:dind
variables:
  DOCKER_DRIVER: overlay2

before_script:
  - echo $CI_REGISTRY_PASSWORD | docker login $CI_REGISTRY -u $CI_REGISTRY_USER --password-stdin

build_and_push:
  script:
    - docker build -t $CI_REGISTRY_IMAGE:latest .
    - docker push $CI_REGISTRY_IMAGE:latest

Takeaway: Always use a PAT with API scope for Docker registry actions; SSH keys are unrelated to container registry authentication.

People also ask

Can I use my GitLab password instead of a PAT?

No, GitLab requires a PAT with API scope for Docker registry operations, especially when 2FA is enabled.

Why does `docker login` fail with a PAT?

Make sure you pipe the PAT into `--password-stdin` and use the correct registry URL; otherwise Docker may treat the token as a password and reject it.

How do I revoke a compromised PAT?

Delete it from *User Settings → Access Tokens* and generate a new one with the same scopes.
