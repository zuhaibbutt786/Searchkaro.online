Stage only modified files in Git, ignoring untracked files

Use `git add -u` or `git commit -a` to stage tracked changes while keeping untracked files ignored by .gitignore.

Why `git add .` pulls untracked files

The dot tells Git to add every file in the current directory, regardless of whether it is tracked. Untracked files are added because they are not already in the index, so `git add .` will stage them. This behavior is by design and cannot be overridden with a simple flag.

`git add -u` stages only tracked modifications

The `-u` (or `--update`) option updates the index only for files that are already tracked. It records modifications and deletions but ignores new files. Run it from the repository root to affect the whole tree:

git add -u :/
# or
git add -u .

Verify that your `.gitignore` is effective

The ignore file only applies to files that are not yet tracked. To double‑check, list ignored files with:

git ls-files -o --exclude-standard
# or test a specific path
git check-ignore -v .metadata/
# The output shows the pattern that matched.

Interactive staging with `git add -p`

If you want fine‑grained control over which hunks of a modified file are staged, use:

git add -p
# Answer the prompts to stage selected changes.

Common pitfalls and quick fixes

• If a file is already tracked, `.gitignore` will not stop it from being staged. Remove it from the index first: `git rm --cached <file>`. • `git commit -a` automatically stages all tracked changes before committing, bypassing the index entirely. • Ensure the `.gitignore` file is committed; uncommitted ignore rules have no effect.

Takeaway: Use `git add -u` to stage only tracked changes; `.gitignore` only blocks new, untracked files.

People also ask

Can I ignore a tracked file without removing it from the index?

Mark it as assume‑unchanged: `git update-index --assume-unchanged <file>`. This tells Git to skip it in status and diff.

What does `git add -A` do compared to `git add .`?

`git add -A` stages all changes, including new, modified, and deleted files, just like `git add .`. It does not respect `.gitignore` for new files.
