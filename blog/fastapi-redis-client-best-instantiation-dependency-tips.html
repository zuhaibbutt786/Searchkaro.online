FastAPI Redis Client: Best Instantiation & Dependency Tips

Learn how to properly create and share a Redis client in FastAPI, avoiding common pitfalls and ensuring efficient resource usage.

Why a Single Connection Matters

Redis connections are expensive to create and close. Re‑creating a client on every request adds latency and can exhaust the server’s connection limit. A shared connection pool keeps the overhead low and guarantees thread‑safe access across async workers.

```python
import redis
client = redis.Redis(host='localhost', port=6379, db=0, decode_responses=True)
```

Module‑Scoped vs Dependency Injection

Defining the client at module level is quick but hides the lifecycle. Each worker process will instantiate its own client, which is fine for simple scripts but makes shutdown handling difficult. Using Depends creates a new client per request, which defeats connection pooling and adds unnecessary overhead.

```python
# module level
r = redis.Redis(host='localhost', port=6379, db=0)
```

Lifespan Events for Connection Lifecycle

FastAPI’s startup and shutdown events allow you to create a client once, store it in `app.state`, and close it gracefully. A dependency that returns `app.state.redis` guarantees the same instance is used in every request.

```python
from fastapi import FastAPI, Depends
import redis

app = FastAPI()

@app.on_event("startup")
async def startup():
    app.state.redis = redis.Redis(host='localhost', port=6379, db=0, decode_responses=True)

@app.on_event("shutdown")
async def shutdown():
    app.state.redis.close()

def get_redis() -> redis.Redis:
    return app.state.redis

@app.get("/foo")
async def foo(r: redis.Redis = Depends(get_redis)):
    return {"message": r.get("foo")}
```

Async Redis with redis‑py

When using async endpoints, switch to `redis.asyncio.Redis` (or `aioredis`). The pattern remains identical: create once on startup, close on shutdown, and expose via Depends.

```python
import redis

@app.on_event("startup")
async def startup():
    app.state.redis = redis.asyncio.Redis(host='localhost', port=6379, db=0, decode_responses=True)

@app.on_event("shutdown")
async def shutdown():
    await app.state.redis.close()

def get_redis() -> redis.asyncio.Redis:
    return app.state.redis
```

Best Practice Recommendation

Create the Redis client once during the application startup, keep it in `app.state`, and provide it to routes via a simple dependency. This approach gives you connection pooling, clean shutdown, and minimal boilerplate.

Takeaway: Instantiate Redis once at startup, store in `app.state`, and inject it with a dependency for efficient, clean FastAPI applications.

People also ask

Can I reuse the same Redis client across requests?

Yes. Store the client in `app.state` and return it from a dependency; it will be reused for all requests.

Does redis‑py automatically pool connections?

Yes, `redis.Redis` uses a connection pool internally; creating one instance per worker is sufficient.
