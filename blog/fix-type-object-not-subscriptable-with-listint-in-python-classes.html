Fix 'type' object not subscriptable with List[int] in Python classes

Learn why List[int] fails in older Python versions and how to correctly import typing for type annotations.

Problem Overview

A common runtime error is "TypeError: 'type' object is not subscriptable" when using annotations like List[int] in a class constructor. The code runs fine on Python 3.9+ but crashes on earlier releases.

Root Cause

The syntax list[int] is only supported from Python 3.9 onward. In older interpreters, list is a plain type and cannot be subscripted. Additionally, installing a third‑party typing package via pip shadows the standard library module, causing import confusion.

Correct Import and Usage

Use the built‑in typing module and its generic types. Remove any pip‑installed typing package. Annotate with typing.List for compatibility with Python 3.5+. Example:

from typing import List

class MyClass:
    def __init__(self, a: int, arr: List[int]):
        self.a = a
        self.arr = arr

    def show(self):
        print('a =', self.a)
        print('arr =', self.arr)

obj = MyClass(1, [1, 2, 3])
obj.show()

Python 3.9+ Alternative

If you are on Python 3.9 or newer, you can use the native list syntax directly, which is shorter and more readable:

class MyClass:
    def __init__(self, a: int, arr: list[int]):
        self.a = a
        self.arr = arr

    def show(self):
        print('a =', self.a)
        print('arr =', self.arr)

obj = MyClass(1, [1, 2, 3])
obj.show()

Common Pitfalls

1. Installing a pip package named typing – this shadows the stdlib module. 2. Mixing annotations from both typing.List and list[int] in the same project. 3. Forgetting that type annotations are optional; the error is purely about syntax, not runtime logic.

Takeaway: Use the built‑in typing module and match your Python version to avoid subscriptable type errors.

People also ask

Do I need to import List from typing on Python 3.9+?

No, you can use list[int] directly; importing List is optional but still works.

What happens if I keep the pip‑installed typing package?

It will shadow the standard library module and can cause import errors or unexpected behavior.

Can I use typing.List for all Python versions?

Yes, typing.List is available from Python 3.5 onward and is the safest choice for backward compatibility.
